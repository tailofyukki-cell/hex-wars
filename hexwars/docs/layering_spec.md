# HEX WARS 立体化（高度レイヤー）仕様書 ドラフト v0.1

本書は `hex_wars_spec.md` への追補（新設 §5.11 相当）。マップを「高さ方向に3段
（**空 / 地表・海面 / 海中**）」へ立体化し、**高さが違えば同一セルに複数ユニットを
共存**できるようにする。攻撃射程は従来どおり**水平ヘクス距離**のみで判定し、高さ差
は射程に影響しない（＝今までと同じ間合いで撃てる）。

---

## 1. 目的と非目標

**目的**
- 1ヘクスに「空・地表(海面)・海中」の3ユニットまで同時に存在できる。
- 例: 同じセルに『駆逐艦（海面）＋潜水艦（海中）＋戦闘機（空）』が重なれる。
- 攻撃・反撃・射程・視界は**水平距離**基準で従来と同じ体験を保つ。

**非目標（今回やらない）**
- 4段以上の高度、地形の標高差、視線遮蔽（LOS）による高低の有利不利。
- 高さ差による命中・ダメージ補正（＝高度は当たり判定に影響しない）。
- レイヤーをまたぐ「積み重ね移動」（下の層を踏み台にする等）。

---

## 2. レイヤーの定義

高度を3段の列挙で表す。**レイヤーはユニット種別（MoveClass）から一意に決まる**。
Unit 構造体に新フィールドは持たせない（＝セーブ互換）。

```c
typedef enum {
    LAYER_AIR = 0,   /* 空: 航空機 */
    LAYER_SURFACE,   /* 地表・海面: 歩兵/車両/戦車 と 水上艦 */
    LAYER_UNDER,     /* 海中: 潜水艦 */
    LAYER_COUNT
} Layer;

/* MoveClass → Layer（純粋関数。core層に置く） */
static inline Layer unit_layer(int mclass) {
    if (mclass == MC_AIR) return LAYER_AIR;
    if (mclass == MC_SUB) return LAYER_UNDER;
    return LAYER_SURFACE;   /* FOOT/WHEEL/TRACK/SEA */
}
```

既存資産との対応:
- `MC_AIR`（FIGHTER/BOMBER/HELI/T_COPTER/DIVE_BOMBER/SCOUT_PLANE/SUPPLY_AIR）→ **空**
- `MC_FOOT/WHEEL/TRACK`（歩兵・車両・戦車）＋ `MC_SEA`（水上艦全般）→ **地表・海面**
- `MC_SUB`（SUBMARINE）→ **海中**

> 補足: 「地表」と「海面」は同じ SURFACE レイヤー。陸ヘクスには地上ユニット、海ヘクス
> には水上艦が乗る（進入可否は従来どおり `terrain.mcost[mclass]` が決める）。両者が
> 同一ヘクスに同時に乗ることは地形進入コストの都合で通常起きない。

## 3. データモデルとAPIの変更

### 3.1 占有（スタッキング）
- 占有単位を **(x, y) から (x, y, layer)** に変更。各(セル,レイヤー)に**最大1体**。
- よって1セルに最大3体（空・地表/海面・海中）。

**関数の変更**
```c
/* 旧: 1セル1体前提 */
int game_unit_at(const Game *g, int x, int y);

/* 新: レイヤー指定で引く（占有判定・移動・戦闘の基礎） */
int game_unit_at_layer(const Game *g, int x, int y, Layer L);

/* 互換ヘルパ（UI/AIの当たり判定用）: そのセルの全レイヤーを返す。
 * 戻り値=体数、out[LAYER_COUNT] に unit index（不在は-1）を格納 */
int game_units_at(const Game *g, int x, int y, int out[LAYER_COUNT]);
```
- 既存 `game_unit_at(x,y)` の呼び出し箇所（占有・移動・ZOC・UI選択・AI）を、
  文脈に応じて `game_unit_at_layer` か `game_units_at` へ置換する。
  - 「そのユニットが入れるか？」＝自分のレイヤーだけ見る → `game_unit_at_layer`。
  - 「そのセルに何がいるか？」＝全レイヤー走査 → `game_units_at`。

### 3.2 セーブ互換
- Unit にフィールド追加なし。レイヤーは type から導出。**SAVE_VERSION 据え置き**。
- 旧セーブは各セル高々1体だったので、そのまま読み込んでも新占有規則に矛盾しない。
- マップ `.map` の `unit = owner,TYPE,x,y[,hp]` 形式も**不変**。同一 (x,y) に
  レイヤーの異なる複数ユニットを列挙可能になる（例: 海面に駆逐艦・海中に潜水艦）。

### 3.3 マップ読込時の安全網（既存 `game_fixup_unit_terrain` の拡張）
- 進入不可地形補正に加え、**同一(セル,レイヤー)重複**を検出したら、片方を最寄りの
  空き(同レイヤー進入可)へBFSで寄せる。データ手編集の事故を防ぐ。

## 4. ルール変更点（§5 への追補）

### 4.1 移動（§5.4）
- 進入可否は従来どおり `terrain.mcost[mclass] > 0`。
- 目的セルの**自分と同じレイヤー**が空いていれば進入・停止できる。他レイヤーに
  敵味方がいても無関係。
  - 例: 敵潜水艦(海中)がいる海面へ、自駆逐艦(海面)は進入して停止できる。
- 通過中セルも同レイヤーの占有のみ判定する（現行 path.c の occ 判定をレイヤー化）。

### 4.2 ZOC（§5.4）
- ZOCは**地表レイヤーだけの現象**。
  - 発生源: 地上ユニット（FOOT/WHEEL/TRACK）。※現行仕様どおり。
  - 影響を受ける側: **SURFACE レイヤーの移動のみ**（地上＋水上艦）。
  - **AIR と UNDER は ZOC を発生させず、受けもしない**（現行 path.c は AIR を既に
    除外済み。SUB も除外を追加）。

### 4.3 戦闘（§5.5）— ★最重要
- 射程判定は**水平ヘクス距離 `hex_distance(fx,fy,tx,ty)` のみ**。高さ差は加算しない。
  → 「高さが違っても今までと同様に攻撃できる」を満たす。
- 攻撃可否は従来のマトリクスがすべて決める:
  `atk[target.armor] > 0` かつ `ammo>0`、潜水艦は `anti_sub` 持ちのみ、視認可能。
  **レイヤー自体による攻撃制限は設けない**（＝空↔海中でも、装甲マトリクスと射程が
  合えば撃てる）。
- 対象列挙 `rules_list_targets` は既に全ユニット走査なので、占有のレイヤー化さえ
  済めば**そのまま多層対応**になる（距離・装甲・対潜・視界で絞る）。

**同一セル・別レイヤー（水平距離0）の扱い**
- 直射ユニット（`range_min <= 1`）は、**同一セルの別レイヤー敵**（距離0）を攻撃可能
  とする。例: 対空戦車(海面)が真上の戦闘機(空)を、駆逐艦(海面)が真下の潜水艦(海中,
  ただし対潜必須)を迎撃。
- 間接ユニット（`range_min >= 2`：自走砲・ロケット砲・戦艦の艦砲等）は**距離0を
  攻撃できない**（自セル直上/直下は撃てない）。従来の「自分の足元は撃てない」感覚を維持。
- 反撃も同じ規則（対象が直射で射程内なら反撃、間接は反撃なし＝現行どおり）。
- 実装は `rules_list_targets` の距離条件を:
  `d >= (range_min>0?range_min:1) && d <= range_max`、ただし
  `d==0` は `range_min<=1` のときのみ許可、へ拡張。

### 4.4 地形防御と高度  ★決定: 全レイヤーに適用
- 地形防御 `def_bonus` を **全レイヤー（空・地表/海面・海中）に適用**する。
  - **現行挙動の変更点**: `battle.c` / `ai.c` は現在 `MC_AIR` の地形防御を0にしている
    （`terrain_def = (dt->mclass == MC_AIR) ? 0 : terr->def_bonus;`）。この分岐を
    **撤去**し、航空機も自セルの地形防御を受けるようにする。潜水艦(UNDER)も同様に
    そのセルの地形防御を受ける。
  - 効果例: 都市/森の上空の航空機、沿岸地形上の潜水艦も防御補正を得る。
  - 注意: これにより航空機の被ダメージが従来より下がる。既存の戦闘ゴールデンテスト
    やAI評価（`ai.c` の `tdef`）の期待値・分岐を合わせて更新すること。
- 高度差そのものによる命中/ダメージ補正は**なし**（非目標）。

### 4.5 索敵・視界（§5.8）
- 視界は水平距離のみ（レイヤー非依存）。現行どおり。
- 潜水艦のステルス（`is_sub`：隣接する `anti_sub` 味方がいる時だけ視認）を維持。
  これが実質「海中レイヤーの隠蔽」を表現する。
- 森・都市の隠蔽（`hide`）は SURFACE の地上ユニットに対してのみ有効（現行どおり）。
- 同一セルに複数レイヤーがいる場合、**各ユニットは自分の可視条件で個別に判定**。
  （例: 海面の駆逐艦は見えるが、同セル海中の潜水艦は対潜が隣接しないと見えない）

### 4.6 輸送・空母（§5.9）
- 搭載中ユニットは従来どおり `UF_LOADED`＝盤外扱い。占有・レイヤーに関与しない。
- 積込みは「乗客が輸送手段のセルへ移動」＝**同一レイヤー内の接触**で行う
  （地上→輸送艦/トラック は SURFACE 同士。航空機→空母は §4.7 参照）。
- **重要な相性**: 空母(海面)が艦載機(空)を発艦後、艦載機は空レイヤーへ出る。
  以後は**空母と艦載機が同一セルに共存**できる（海面＝空母、空＝艦載機）。
  空母の艦載機補給（`resupply_cargo`）は搭載中(=盤外)にのみ作用する現行仕様を維持。

### 4.7 積込みのレイヤー跨ぎ（空母×航空機）
- 空母は SURFACE、艦載機は AIR。積込みは「レイヤーが違うが**同一セルで**行う特例」。
  - 発艦: 空母セルの AIR が空いていれば、艦載機はそのセル(空)へ降ろす（`game_unload`）。
  - 着艦(搭載): 艦載機が空母セルへ移動し「搭載」を選ぶと `UF_LOADED`（盤外）。
- 実装注意: 現行 `game_can_board`/`game_load_unit`/`game_unload_unit` は
  レイヤー非依存で動くが、**発艦先(空)・着艦元(空)の占有はAIRレイヤーで判定**する。

### 4.8 占領・補給・回復
- 占領: SURFACE の地上ユニット（`can_capture`）のみ。現行どおり。
- 補給/回復（補給車=陸/補給機=空/補給艦=海）: `move_domain` によるドメイン制限は
  現行維持。レイヤーとドメインは別概念（ドメイン=陸/空/海の3分類）で、両立させる。

## 5. UI/描画（§8 への追補）

### 5.1 セル選択（クリック/カーソル）  ★決定: 小ポップアップ方式
- 1セルに複数ユニットがいる場合の選択規則:
  1. カーソルセルにユニットが**1体**なら従来どおり即選択。
  2. 複数（最大3）なら、そのセルをクリック/決定した時点で**小ポップアップ（レイヤー
     選択メニュー）**を開き、`[空] 戦闘機「Fk-9型」` のように各レイヤーの中身を1行で
     並べて直接選ばせる。↑↓/クリックで選択、X/右クリックで閉じる。
  3. 情報パネルには選択後のユニット＝そのレイヤーを表示。
- 攻撃対象選択も同様: 同一セルに複数の敵がいる場合、対象確定時に同じ小ポップアップで
  どのレイヤーの敵を撃つか選ばせる。
- 実装メモ: 既存の行動メニュー（`BS_ACTION_MENU`）や生産メニュー（`BS_PRODUCTION`）と
  同じ「メニュー矩形＋↑↓/クリック」パターンを流用し、新状態 `BS_LAYER_PICK` を追加する。
  ポップアップ項目数は最大3。

### 5.2 レンダリング（重なりの可視化）
- 同一セルの複数ユニットを見分けるため、レイヤーごとに描画をずらす:
  - **空**: 上方向に小オフセット＋影（浮遊表現）。
  - **地表/海面**: 通常位置。
  - **海中**: 半透明＋下方向に小オフセット（沈降表現）。
- セル右上に**レイヤーバッジ**（空=▲/海面=●/海中=▼）と体数を小さく表示。
- 選択中/対象候補ユニットのレイヤーを枠色で強調。
- 情報パネル（下部）は選択レイヤーのユニットを表示。既存の「搭載ユニットの状態」
  ボックス（`draw_cargo_detail`）はそのまま流用。

### 5.3 移動範囲・攻撃範囲表示
- 選択ユニットのレイヤーに基づき、到達可能セル（同レイヤー占有のみ考慮）を着色。
- 攻撃可能セルは水平距離＋マトリクスで着色（現行ロジックを占有レイヤー化するだけ）。

## 6. AI（§7 への追補）
- 脅威マップ・対象評価・生産は、占有のレイヤー化に追随させる:
  - `game_unit_at` 依存箇所を `game_unit_at_layer`/`game_units_at` に置換。
  - 目標選択は現行の全ユニット走査ベースなので、距離・装甲・対潜条件で自然に多層対応。
- 追加の高度AIは不要（高度差補正が無いため）。ただし「同一セルに潜り込んで
  張り付く」等の高度戦術はスコープ外（将来拡張）。

1. **L0 基盤**: `Layer`/`unit_layer`/`game_unit_at_layer`/`game_units_at` を追加。
   既存 `game_unit_at` の呼び出しを機械的に置換（挙動は現状維持＝各セル1体のまま）。
   → ここまでで回帰ゼロ（テスト全緑）を確認。
2. **L1 占有解禁**: 移動・停止・path の占有判定を同レイヤー化。多層共存を許可。
   `game_fixup_unit_terrain` に重複解消を追加。
3. **L2 戦闘**: 距離0特例、ZOC/地形防御のレイヤー規則、対象列挙の確認。
4. **L3 UI**: セル選択のレイヤー巡回、重なり描画、レイヤーバッジ、範囲表示。
5. **L4 AI**: 占有レイヤー化の追随、対象選択の確認。 → **2026-08-28 実装済み**
   - 脅威マップを**被弾側の装甲カテゴリ別**に持つ（`AiState.threat[ARMOR_COUNT][H][W]`）。
     従来は全カテゴリの最大値1枚だったため、高射砲の対空95が戦車の脅威にも数えられ、
     空・陸・海が互いの脅威に引きずられて動きが鈍っていた。
   - 前進目標を「実際にダメージを与えられる敵」優先に（`nearest_target_goal`）。
     **ただし敵首都を必ず候補に残すこと**（`advance_goal`）。外すと部隊が殴り合いに
     終始して首都へ進まず、決着が減って損失だけ増える（実測: 決着6→4・損失+26%）。
   - 脅威の重み `THREAT_DIV` は 8 が最良。5(慎重)も10(大胆)も決着が減り損失が増えた。
6. **L5 コンテンツ**: 立体戦を活かすマップを追加。 → **2026-08-28 実装済み**
   - `game_can_produce_at` / `game_type_buildable_at` をレイヤー別に。
   - `tools/gen_maps.py` の占有を `(セル,高さ)` 単位にし、引数で1枚だけ生成可能に。
   - `m04_layers.map`「三層の要衝」を追加（同一セルに空/海面/海中を重ねた初期配置）。
- 各段階で `test_core` / `sim_ai` を通し、`build_and_deploy` で配布同期。

## 9. 決定事項（ユーザー確認済み 2026-07-22）
1. **距離0（同一セル別レイヤー）攻撃**: 直射のみ可・間接不可。→ **確定**
2. **地形防御**: **全レイヤーに適用**（AIR/UNDER も自セルの `def_bonus` を受ける）。
   → **確定**（§4.4。現行の「MC_AIR は地形防御0」の分岐を撤去する変更を含む）
3. **セル選択UI**: **小ポップアップ**でレイヤーを直接選択（新状態 `BS_LAYER_PICK`）。
   → **確定**（§5.1）
4. **ZOC**: SURFACE 限定（地上が発生源、地上＋水上艦が影響を受ける。空・海中は無関係）。
   → 既定どおり採用
5. **潜水艦の隠蔽**: 現行 `is_sub`＋対潜隣接ルールを海中レイヤーの表現として維持。
   → 既定どおり採用
6. **セーブ互換**: フィールド追加なし・SAVE_VERSION据え置き。→ 既定どおり採用
7. **空母×艦載機の同一セル共存**: 許可（発艦後に海面=空母／空=艦載機で重なる）。
   → 既定どおり採用
