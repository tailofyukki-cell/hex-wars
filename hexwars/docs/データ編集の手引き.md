# データ編集の手引き

画像・名前・ユニット性能・マップを手で書き換えるときの、**どこを触ればいいか**の一覧。
ゲームの中身はほとんど `data/` のテキストと `assets/` の画像・音でできていて、
**C のソースを触らずに変えられる**。

---

## 0. まずこれだけ

### 変更が画面に届くまで

```
hexwars/data/    ← ここを編集する（正本）
hexwars/assets/  ←

        ↓ build_and_deploy.bat をダブルクリック

hexwars/build/data, build/assets      ← 開発中に遊ぶ用
HexWars_配布/data, HexWars_配布/assets  ← 人に渡す用
```

- **`data/` と `assets/` の編集に再ビルドは要らない。** テキストと画像は起動時に読まれる。
  それでも `build_and_deploy.bat` は実行すること。**コピーが走らないと古いままの build を見続ける**。
- C のソース（`src/`）を触ったときだけ本当のビルドが要る。同じバットで両方やってくれる。
- **`build/data/` を直接編集しないこと。** 次のビルドで正本から上書きされて消える。

### 絶対に守ること

| | 理由 |
|---|---|
| **`units.def` / `terrain.def` にエントリを足すときは必ず末尾** | セーブデータは種別を**番号**で持っている。途中に挿すと既存のセーブの中身が全部ずれる |
| **`data/maps/test_arena.map` は変更しない** | 単体テストが座標を決め打ちで見ている。ファイル先頭にも書いてある |
| **ユニット名は48バイト未満（日本語15文字まで）** | 超えると起動時に読み込みエラーで止まる |

### 編集したら

```bash
python tools/gen_unit_names.py --check   # 名前の長さと重複（名前を触ったとき）
build\test_core.exe                      # ルールが壊れていないか
build\sim_ai.exe                         # CPU同士で全マップ完走するか（約1分）
```

`test_core.exe` と `sim_ai.exe` は **`hexwars/` を作業フォルダにして**起動すること。
リポジトリ直下から叩くと `data/` が開けず全部こける。

## 1. 画像を差し替える

**同じ名前で上書きすれば、それだけで反映される。**ファイルが無いときは落ちずに
図形や単色にフォールバックするので、用意できたものから順に差し替えればよい。

差し替えできる画像の全一覧と、まだ用意できていないものは **[asset_list.md](asset_list.md)** にある
（`python tools/gen_asset_list.py` で作り直せる）。

### どこに何があるか

| 置き場所 | 何の絵か | 指定している場所 | 実寸の目安 |
|---|---|---|---|
| `assets/gfx/terrain/` | マップのマス | `data/terrain.def` の `image` | 192×192 正方形 |
| `assets/gfx/units/` | 盤上のユニット | `data/units.def` の `image` | 96×96 透過 |
| `assets/gfx/co/` | 指揮官の顔 | `data/commanders.def` の `image` | 240×320 |
| `assets/gfx/brief/` | 作戦前の1枚絵 | `data/campaign/main.cpn` の `art` | 横800基準 |
| `assets/gfx/reward/` | クリア後のご褒美 | `main.cpn` の `reward` | 640×480 |
| `assets/gfx/cutin/` | 攻撃時のカットイン | `units.def` / `commanders.def` の `cutin` | 縦長 |
| `assets/gfx/anim/` | 戦闘アニメ動画 | `units.def` の `anim` | mp4 / GIF |

### 地形の絵を描くときの注意

- **必ず「真上から見た地面の模様」にする。** 斜め見下ろし表示では縦0.6倍に潰れる。
  地面の模様なら潰れても自然に見えるが、木や建物を横から見た形で描くと不自然になる。
  森は樹冠、街は屋根、山は岩肌を真上から描いてある。
- 六角形の内側にクリップして貼るので、**正方形PNGで全面を塗ればよい**（四隅は見えなくなる）。
- **基調色は `terrain.def` の `color` と揃える。** タイルの側面（崖）は `color` で塗られるので、
  ずれると天面と側面が食い違って見える。
- **`road.png` だけは例外で、舗装の帯を描き込んではいけない。** 絵に帯を焼き込むと向きが
  固定され、縦に走る道でも横向きの舗装が出る。舗装は隣接マスを見て描画側が繋いで描く
  （`terrain.def` の `link_road`）。road.png には路肩の地面だけを描くこと。

### 陣営ごとに別の絵にする

`units.def` の `image` は全陣営共通。陣営ごとに変えたいときは `image` の**あと**に書く。

```
[unit TANK]
image  = gfx/units/tank.png        # 全陣営これ
image0 = gfx/units/tank_blue.png   # 陣営0（自軍）だけ
image1 = gfx/units/tank_red.png    # 陣営1だけ
```

番号は陣営番号（0〜4）。書かなかった陣営は `image` のまま。
**描画時に陣営色を乗せない**（陣営は足元のチップの色で示す）ので、色分けした絵が欲しければ
ここで指定する。元絵を陣営色に染めた仮絵なら `python tools/gen_unit_tint.py --apply` で一括生成できる。

### 仮絵を作るツール（要 Pillow）

```bash
python tools/gen_terrain_gfx.py   # 地形タイル
python tools/gen_units_gfx.py     # ユニット
python tools/gen_co_art.py        # 指揮官の顔
python tools/gen_brief_art.py     # ブリーフィング
python tools/gen_reward_art.py    # クリア絵
python tools/gen_cutin_art.py     # カットイン
```

どれも差し替え前提のプレースホルダ。**手で描いた絵を同じ名前で上書きすればそのまま置き換わる。**

## 2. 名前を変える

| 変えたいもの | ファイル | キー |
|---|---|---|
| ユニット名 | `data/units.def` | `name`（陣営別は `name0`〜`name4`） |
| 地形名 | `data/terrain.def` | `name` |
| 指揮官の名前・肩書き・説明 | `data/commanders.def` | `name` / `title` / `desc` |
| 必殺技の名前と説明 | `data/commanders.def` | `power_name` / `power_desc` |
| 作戦名・あらすじ | `data/campaign/main.cpn` | `title` / `story` / `brief` |
| マップ名 | `data/maps/*.map` | `[map]` の `name` |
| 陣営名（西方同盟など） | `data/text_ja.def` | `FACTION0`〜`FACTION4` |
| 画面のあらゆる文言 | `data/text_ja.def` | 各キー |

### ユニット名を陣営ごとに変える

```
[unit TANK]
name      = 中戦車「T-40型」      # 全陣営これ
name1     = 中戦車「ZK-40」       # 陣営1（敵）だけ
name2     = 豹
```

`image` と同じ書き方で、`name` の**あと**に書く（後勝ち）。全兵種を揃える必要はない。

- **参照は `id` で行われるので、名前をいくら変えてもルールは変わらない。**
  進化先の解決もキャンペーンの条件判定も `[unit XXX]` の XXX を見ている。
- 5陣営ぶんの名前案は `tools/gen_unit_names.py` に入っている。
  `--check` で長さと重複を確認、`--apply` で `units.def` へ一括投入できる。

### 画面の文言

`data/text_ja.def` は `キー = 文言` の羅列。`%d` `%s` を含むものは**個数と並びを変えないこと**
（書式が合わないと表示が壊れる）。再ビルドは要らない。

## 3. ユニット性能を調整する

`data/units.def`。1ユニット = 1つの `[unit ID]` ブロック。

### 基本

| キー | 意味 | 備考 |
|---|---|---|
| `class` | 移動種別 | `LAND_FOOT` `LAND_WHEEL` `LAND_TRACK` `AIR` `SEA` `SEA_SUB` |
| `armor` | 被弾時の装甲区分 | `SOFT` `HARD` `AIR` `SEA` |
| `cost` | 生産価格（G） | 進化にはこの**2倍**の資金が要る |
| `move` | 移動力 | **平地換算のマス数**。道路はコスト半分なので倍進める |
| `fuel` | 燃料の最大値 | 平地1マスにつき1減る（道路2マスで1）。**燃料が `move` より少ないとそこまでしか動けない** |
| `ammo` | 弾薬の最大値 | 補給ユニットではこれが「補給物資」になる |
| `vision` | 索敵範囲 | 夜は -2（夜間ユニットは落ちない） |
| `def` | 防御力 | |
| `upkeep` | 毎ターンの維持費 | |

### 攻撃力

`atk_soft` / `atk_hard` / `atk_air` / `atk_sea` の4つ。**相手の `armor` に対応するものが使われる。**

**値はダメージ×10。** `55` なら満HPのとき期待値5.5ダメージ。`0` はその区分に攻撃できない。

| キー | 意味 |
|---|---|
| `range_min` / `range_max` | 射程。`range_min` が2以上＝間接攻撃で、**反撃を受けない** |
| `move_and_fire` | 1=移動してから攻撃できる。**0 にすると「動いたらその手番は撃てない」**（間接砲はこれを0にしてある） |
| `anti_sub` / `detect` | 1=潜水艦を攻撃できる |
| `is_sub` / `stealth` | 1=潜水艦。`anti_sub` 持ちからしか攻撃されない |

**射程が長いほど威力が落ちる**（最短射程から1マス遠ざかるごとに -5%、下限50%）。
射程を伸ばす調整をするときはここを織り込むこと。

### 役割

| キー | 意味 |
|---|---|
| `can_capture` | 1=建物を占領できる |
| `capacity` | 搭載できる数（輸送ユニット。上限4） |
| `transport_by` | このユニットを載せられる輸送手段のID（カンマ区切り、最大4） |
| `paradrop` | 1=隣接ではなく**真下**へ降ろせる（空挺） |
| `supply` | 1=補給ユニット。`ammo` が補給物資になる |
| `resupply_cargo` | 1=搭載中のユニットを毎ターン補給する |
| `engineer` | 1=工兵。地形を壊す／直せる |
| `recon` | 1=偵察。索敵で1歩進むごとに経験値+1 |
| `night` | 1=夜間ユニット。夜に攻撃+50%、視界が落ちない |
| `no_fuel` | 燃料切れの挙動。`NONE` / `DIE`（墜落）/ `DAMAGE`（漂流） |
| `move_se` | 移動音。`MOVE_FOOT` `MOVE_VEHICLE` `MOVE_AIR` |

### 進化

```
evolve_to  = TANK_V    # 経験値満タン＋自軍の補給拠点の上で進化できる先
no_produce = 1         # 生産メニューに出さない（進化でしか手に入らない）
```

進化先も普通の `[unit]` ブロックとして書く。**必ずファイルの末尾に足すこと。**

### 調整したら必ず

```bash
build\test_core.exe   # ルールの回帰
build\sim_ai.exe      # CPU同士で全マップ完走（約1分）
```

`sim_ai` は勝敗・ターン数・損失を出す。**バランスを見るときは1シードで判断しないこと**
（シードによる振れが大きい）。全部回すなら `HWSIM_ALL=1`、マップを絞るなら `HWSIM=c05` など。

## 4. 地形を調整する

`data/terrain.def`。

| キー | 意味 |
|---|---|
| `char` | `.map` の中でこの地形を表す1文字 |
| `def` | 防御補正（%） |
| `cost_foot` / `cost_wheel` / `cost_track` / `cost_air` / `cost_sea` / `cost_sub` | 移動コスト。**2倍整数**（道路=1, 平地=2, **0=進入不可**） |
| `income` | 1ターンの収入 |
| `capturable` | 1=占領できる |
| `produces` | 生産できる種別。`LAND` / `AIR` / `SEA` |
| `supplies` | 補給対象の移動種別（カンマ区切り） |
| `hide` | 1=隣接しないと中の敵が見えない（森・都市） |
| `hq` | 1=首都。落とされると負け |
| `breaks_to` | 工兵に壊されたときになる地形ID（空=壊せない） |
| `repair_cost` | この地形へ直すのに要る資金 |
| `height` | **見た目だけの起伏。**ルールには一切影響しない |
| `link_road` | 道路の接続描画。1=道路そのもの / 2=道が伸びてくる先（街など） |
| `color` | 単色描画と、タイル側面（崖）の色 |

### いま使われている文字

| 文字 | 地形 | ID | 防御 | 収入 | height |
|---|---|---|---|---|---|
| `.` | 平地 | PLAIN | 0 | — | 0 |
| `=` | 道路 | ROAD | 0 | — | 0 |
| `w` | 森 | FOREST | 20 | — | 4 |
| `^` | 山 | MOUNTAIN | 40 | — | 22 |
| `r` | 川 | RIVER | 0 | — | -3 |
| `~` | 海 | SEA | 0 | — | -7 |
| `c` | 都市 | CITY | 30 | 100 | 3 |
| `f` | 工場 | FACTORY | 30 | 150 | 3 |
| `a` | 空港 | AIRPORT | 20 | 100 | 2 |
| `p` | 港 | PORT | 20 | 100 | 1 |
| `h` | 丘 | HILL | 20 | — | 11 |
| `H` | 首都 | HQ | 40 | 300 | 5 |
| `x` | 圏外 | VOID | 0 | — | 0 |
| `A` | 野戦飛行場 | AIRSTRIP | 20 | 80 | 2 |
| `P` | 泊地 | ANCHORAGE | 20 | 80 | 1 |
| `X` | 瓦礫 | RUBBLE | 20 | — | 2 |
| `Y` | 破壊された港湾 | RUBBLE_PORT | 15 | — | 0 |

`x`（圏外）は全移動コスト0で進入不可、かつ**描画もされない**。これでマップの輪郭を
長方形以外の自由な形にしている。

## 5. マップを調整する

`data/maps/*.map`。4つのセクションでできている。

```
[map]                       ← 広さ・ターン数・勝利条件・天候など
name   = 河川突破
width  = 42
height = 25
turns  = 62
funds0 = 1750               ← 陣営ごとの初期資金（funds0〜funds4）

[terrain]                   ← 地形を1行1列で並べる
row = xxx..f........w.....xxxxxxxxxxxxxxxxxxxxxx
row = xxx...........w.....xxxxxxxxxxxxxxxxxxxxxx

[owners]                    ← 建物の初期所有者
own = 29,21,1               ← x, y, 陣営番号

[units]                     ← 初期配置
unit = 0,INFANTRY,14,9      ← 陣営, ユニットID, x, y [, HP]
```

### `[map]` で使えるキー

| キー | 意味 |
|---|---|
| `name` | マップ名 |
| `width` / `height` | 広さ。`row` の本数・文字数と合わせる |
| `turns` | ターン上限 |
| `timeout_winner` | ターン切れのときの勝者。陣営番号、`-1`=引き分け。防衛戦は `0` にして「持ちこたえれば自軍の勝ち」にする |
| `funds0`〜`funds4` | 陣営ごとの初期資金 |
| `income_scale` | 収入の倍率（%） |
| `team0`〜`team4` | 同盟。同じ番号どうしは味方 |
| `leader0`〜`leader4` | **チーム**の主力陣営。`leader<チーム番号> = 陣営番号`（未指定なら所属する最小の陣営番号） |
| `objective_count` / `objective_player` | 拠点をn個確保したら勝ち |
| `weather` | 1=天候あり |
| `weather_clear` / `weather_cloudy` / `weather_rain` | 天候の抽選重み（既定 60 / 30 / 10） |
| `weather_fixed` | 天候を固定（0=晴 1=曇 2=雨） |
| `night` | 0=昼夜なし、1=あり |
| `day_turns` / `night_turns` | 昼夜の周期。**`day_turns = 0` で常夜** |

### 座標の取り方

**奇数行が右に半マスずれるポイントトップ配置（odd-r）。** `row` の1行目が y=0、
各行の1文字目が x=0。座標を数えるときは `[terrain]` の行をそのまま数えればよい。

### 新しいマップを足すとき

1. `data/maps/` に `.map` を置く
2. **`data/maps/maplist.txt` に1行足す**（`maps/ファイル名|表示名`）。これでフリー対戦に出る
3. キャンペーンに載せるなら `data/campaign/main.cpn` にノードを足す
4. `tests/sim_ai.c` に1行足すと、**パースと完走が自動で検証される**

### マップのツール

```bash
python tools/gen_maps.py m04      # 1枚だけ生成し直す
python tools/scale_maps.py 1.6    # 全マップを拡大（地形は最近傍、建物とユニットは再配置）
python tools/add_airports.py      # 全マップに空港を増設
```

**`gen_maps.py` を引数なしで実行しないこと。** 全マップが scale 前の小さいサイズに戻る。

## 6. キャンペーンを調整する

`data/campaign/main.cpn`。1作戦 = 1つの `[node ID]` ブロック。

| キー | 意味 |
|---|---|
| `map` | 使うマップ（`maps/xxx.map`） |
| `title` | 作戦名 |
| `brief` / `story` / `story_win` | 作戦前・勝利後の文章 |
| `art` / `reward` / `reward_video` | ブリーフィング絵・クリア絵・クリア動画 |
| `next_win` / `next_lose` | 勝ったとき／負けたときの次のノード |
| `next_win_fast` / `fast_turns` | nターン以内に勝つと別ルートへ |
| `par_turns` | 評価（ランク）の基準ターン |
| `carry` / `bonus` | 持ち越し部隊・ボーナス資金 |
| `enemy_co` | 敵の指揮官 |
| `enemy_scale` / `enemy_waves` | 敵の総数を自軍の割合に揃え、増援として分割投入する |
| `event` | 途中で起きるイベント |
| `no_reinforce` | 1=増援なし |

- **`enemy_scale` は敵を増やす方向にしか働かない。** マップ側の敵は自軍の初期数以下にしておくこと。
- 作戦数の上限は `MAX_CAMPAIGN_MAPS`（現在20）で、**いま使い切っている**。
  足すときは定数とセーブの `rank[]` の幅を同時に見ること。
- 作戦全体図のヘクスに出る番号は `start` から `next_win` をたどった**通し番号**。
  ノードIDは書いた順の名残なので順不同でよい。

## 7. 音を差し替える

`data/audio.def`。`assets/bgm/` `assets/se/` の wav を指すだけ。

```
[music ENDING]
file = bgm/bgm_ending.wav
```

- 戦闘BGMは `[battle]` を足すと**オプション画面の選択肢が増える**（最大12曲）。
- 仮の曲と効果音は `python tools/gen_audio.py` で手続き生成したもの。
- ファイルが無いときは鳴らないだけで、落ちはしない。

## 8. 英語（表示言語）を編集する

ゲームは日本語と英語を切り替えられる（オプションのいちばん上「言語 / Language」）。
初回起動は OS の言語で決まる（日本語環境なら日本語、それ以外は英語）。

### 画面の文言

`data/text_en.def`。`text_ja.def` と**同じキー**で英文を書く。
英語で表示するときは日本語の上に重ねて読むので、**書き漏らしたキーは日本語のまま出る**（キー名が画面に出ることはない）。

### データの中の文章・名前

**どのデータファイルでも、キーの後ろに `@en` を付けた行を足すだけ。**
英語のときはそちらが使われ、日本語のときは読み飛ばされる。

```
[unit TANK]
name      = 中戦車「T-40型」
name1     = 中戦車「ZK-40」
name@en   = T-40 Medium Tank      ← 元の行の**あと**に書く（後勝ち）
name1@en  = ZK-40 Medium Tank
```

| 使える場所 | 例 |
|---|---|
| `units.def` | `name@en` `name1@en`〜`name4@en` `icon@en` |
| `terrain.def` | `name@en` |
| `commanders.def` | `name@en` `title@en` `desc@en` `power_name@en` `power_desc@en` |
| `audio.def` | `name@en`（効果音セット名・曲名） |
| `maps/*.map` | `name@en` |
| `campaign/main.cpn` | `name@en` `title@en` `brief@en` `story@en` `story_win@en` `sub_desc@en` `event_msg@en` |
| `maps/maplist.txt` | 3列目に英語名: `maps/xxx.map|日本語名|English name` |

キャンペーンの注意:

- `brief@en` `story@en` `story_win@en` は**最初の1行が来た時点で日本語の行を全部捨てる**。英語の行だけを並べればよい
- イベントと副目標は**文だけ**を差し替える。`event_msg@en` / `sub_desc@en` を、その作戦の
  `event` / `sub` と**同じ順番・同じ数**だけ書く（条件は日本語側の行がそのまま使われる）
- 各作戦の末尾に `# --- English ---` としてまとめてある

### 長さの上限（英語は1文字1バイト）

| 項目 | 上限 |
|---|---|
| ユニット名 | 47文字 |
| 地形名・指揮官名・必殺技名 | 31文字 |
| 作戦名 | 63文字 |
| ブリーフィング・幕間の1行 | 127文字（画面幅では**約100文字**まで） |
| イベントの知らせ | **63文字** |
| 副目標の説明 | 95文字 |

### 英語で気をつけること

- **`#` は使えない**（行のどこにあってもそこから先がコメントになる）
- 行頭の空白は削られる。どうしても空白が要るときはノーブレークスペース（U+00A0）を使う
- `%d` `%s` の数と順番は日本語と揃える
- ユニット名は `python tools/gen_unit_names.py --check` で英語も含めて長さと重複を確認できる
- `test_core` の `test_language` が、キャンペーンの題・イベント・副目標、ユニット名、地形名、
  マップ一覧に**英語の訳し漏れが無いか**を見ている

### 英語で画面を撮る

```bash
set HWLANG=en
```

`HWLANG` は設定ファイルの言語を書き換えない（撮り終わっても自分の設定は日本語のまま）。

## 9. 確認のしかた

### 画面を見ずに1枚だけ撮る

```bash
set HWSHOT=shot.png
set HWSHOT_FRAME=220
set HWZOOM=2
set HWCAM=19,13
build\hexwars.exe --screen battle 5
```

| 環境変数 / 引数 | 意味 |
|---|---|
| `HWSHOT=<path>` | 最初のフレームをPNGで保存して終了する |
| `HWSHOT_FRAME=N` | Nフレーム後に撮る。**付けないと開幕バナーが被る** |
| `HWCAM=x,y` | 見る位置。`HWZOOM=0..2` で寄り具合 |
| `--screen battle <maplist番号>` | そのマップを索敵OFFで開く |
| `--screen options` / `load` / `endroll` / `result` | その画面を直接開く |
| `--screen story <ノードID>` / `cpnmap <ノードID>` / `cpn <ノードID>` | 幕間・作戦全体図・その作戦のブリーフィング |
| `HWLANG=en` | 英語で起動する（設定は書き換えない） |

`HWCAM` は**カメラは動くがユニットパネルには部隊が出ない**（カーソルが後で動く）。
ユニットの表示を確かめたいときは画面ではなく `test_core` を使うこと。

### よくある失敗

| 症状 | 原因 |
|---|---|
| 編集したのに変わらない | `build_and_deploy.bat` を実行していない。または `build/data/` を直接編集した |
| 起動時に「読み込みエラー」 | `.def` の書式ミス。エラーに**ファイル名と行番号**が出るのでそこを見る |
| 古いセーブが読めなくなった | `.def` の途中にエントリを挿した。末尾に移すこと |
| テストが大量に落ちる | 作業フォルダが違う。`hexwars/` から実行すること |
| ビルドが LNK1104 で失敗 | `hexwars.exe` が起動中。閉じてから |
