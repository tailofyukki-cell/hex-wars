# 別ゲームの作り方（ファンタジー版・SF版などへの作り替え）

このエンジンは「六角形マップのターン制戦略」という骨格だけを持っていて、
**世界観に関わる部分はほぼ全部 `data/` の中にあります。**

作り替えの手順は「プロジェクトのフォルダをまるごとコピーして、`data/` と
`assets/` を書き換える」だけです。C のコードを触る必要があるのは、
このドキュメントの最後にある「7. C を触らないと変えられないもの」だけです。

---

## 1. まず最初に

1. `hexwars` フォルダをまるごとコピーして、新しい名前にする
2. `saves/` `build/` `progress.cfg` `options.cfg` を消す（前のゲームの記録なので）
3. `data/` と `assets/` を書き換えていく

**セーブデータは互換性がありません。** 別ゲームなので当然ですが、
うっかり古いセーブを混ぜると壊れます。必ず消してから始めてください。

---

## 2. 書き換えるファイル（この6つでほぼ全部）

| ファイル | 中身 |
|---|---|
| `data/units.def` | ユニットの種類と性能・絵 |
| `data/terrain.def` | 地形の種類・移動コスト・防御 |
| `data/text_ja.def` | **画面に出る文言のすべて**（ウィンドウのタイトルも `WINDOW_TITLE`） |
| `data/commanders.def` | 指揮官（CO）と必殺技 |
| `data/audio.def` | BGM・効果音 |
| `data/maps/*.map`<br>`data/campaign/main.cpn` | マップとキャンペーン |

`assets/` の中身（絵・音）は `data/` から名前で参照されるので、
好きなファイル名で置けます。詳しくは `assets/差し替えガイド.txt`。

---

## 3. いちばん大事な「読み替え表」

エンジン内部の名前は現代戦のままですが、**画面には一切出ません。**
中身を別のものとして使って構いません。ここが作り替えの肝です。

### 移動タイプ（`units.def` の `class =`）

6種類の「移動の枠」です。名前は内部用なので意味は自由に決められます。

| 内部の名前 | 現代戦での意味 | ファンタジーなら | SFなら |
|---|---|---|---|
| `LAND_FOOT` | 歩兵 | 歩兵・冒険者 | 生身の兵 |
| `LAND_WHEEL` | 装輪車両 | 騎兵・獣 | ホバー |
| `LAND_TRACK` | 装軌車両 | 大型モンスター・攻城兵器 | 歩行戦車 |
| `AIR` | 航空機 | 飛竜・天馬 | 戦闘機・浮遊艇 |
| `SEA` | 水上艦 | 帆船 | 浮遊母艦 |
| `SEA_SUB` | 潜水艦 | 海棲魔物 | 潜航艇 |

**重要な性質:**
- `AIR` は自動的に「空レイヤー」になり、地上ユニットと同じマスに重なれます
- `SEA_SUB` は「海中レイヤー」になり、水上艦と重なれます
- それ以外はすべて「地表レイヤー」で、1マスに1体だけ
- 補給は**同じ系統どうし**でしか行えません（陸=FOOT/WHEEL/TRACK、空=AIR、海=SEA/SUB）

### ダメージ区分（`units.def` の `armor =` と `atk_* =`）

4区分あります。**表示名は `text_ja.def` の1行で決まります。**

```
PANEL_ATK_FMT = 攻: 軟%d 装%d 空%d 海%d      ← 現代戦
PANEL_ATK_FMT = 攻: 物%d 魔%d 飛%d 水%d      ← ファンタジー例
```

| 内部の名前 | 現代戦 | ファンタジー例 |
|---|---|---|
| `SOFT` | 非装甲（歩兵） | 生身 |
| `HARD` | 装甲（戦車） | 重装甲・ゴーレム |
| `AIR` | 航空機 | 飛行 |
| `SEA` | 艦船 | 水棲 |

「対空攻撃力」を「対不死攻撃力」として使う、といったことができます。

### 生産施設（`terrain.def` の `produces =`）

`LAND` / `AIR` / `SEA` の3種類。工場・空港・港 → 兵舎・竜舎・造船所、など。

## 4. ユニットの書き方

```
[unit DRAGON]                    ← 内部ID（英数と _ のみ。マップから参照される）
name      = 火竜                 ← 画面に出る名前
icon      = 竜                   ← 絵がないときの1文字表示
image     = gfx/units/dragon.png ← 両陣営共通の絵
image0    = gfx/units/dragon_b.png   ← 自軍だけ差し替える場合
image1    = gfx/units/dragon_r.png   ← 敵軍だけ差し替える場合
anim      = gfx/anim/dragon.mp4  ← 戦闘アニメ（任意）
class     = AIR                  ← 移動タイプ（上の表）
armor     = AIR                  ← 被弾時の区分
cost      = 1200                 ← 生産費
move      = 7                    ← 移動力
fuel      = 99                   ← 燃料（読み替え可: 魔力など）
ammo      = 5                    ← 弾薬（読み替え可: 詠唱回数など）
vision    = 4                    ← 視界
atk_soft  = 75                   ← 各区分への攻撃力（×10表記。55なら期待5.5ダメージ）
atk_hard  = 45
atk_air   = 60
atk_sea   = 40
def       = 20                   ← 防御
range_min = 1                    ← 射程（1-1なら直射、2以上なら間接）
range_max = 1
can_capture    = 0               ← 1で拠点を占領できる
move_and_fire  = 1               ← 1で移動後に攻撃できる（直射向け）
detect         = 0               ← 1で「隠密ユニット」を攻撃できる（旧名 anti_sub）
stealth        = 0               ← 1で「隠密ユニット」になる（旧名 is_sub）
upkeep         = 0               ← 補給施設の外にいる間、毎ターン減る燃料
no_fuel        = NONE            ← 燃料0のとき: NONE=何もない / DIE=失われる / DAMAGE=毎ターンHP-1
move_se        = MOVE_AIR        ← 移動時の効果音（役割名。省略すると class から自動）
supply         = 0               ← 1で補給ユニット（ammoが物資になる）
capacity       = 0               ← 輸送できる数（0=輸送不可）
resupply_cargo = 0               ← 1で搭載中のユニットを毎ターン補給（空母相当）
transport_by   = T_SHIP          ← このユニットを載せられる輸送手段のID（複数可）
```

**`stealth` / `detect` について:** 効果は「`stealth` のユニットは隣接しないと
見えず、`detect` を持つ相手からしか攻撃されない」です。もとは潜水艦と対潜装備の
仕組みですが、**透明な幽霊とその看破**、**地中を進む敵**などにそのまま使えます。
（旧名 `is_sub` / `anti_sub` も引き続き使えます）

**`upkeep` / `no_fuel` について:** 書かなければ `class` から現代戦の既定値が入ります。

| class | 既定の upkeep | 既定の no_fuel |
|---|---|---|
| `AIR` | 4（空中維持コスト） | `DIE`（墜落） |
| `SEA` / `SEA_SUB` | 0 | `DAMAGE`（漂流） |
| それ以外 | 0 | `NONE` |

**飛竜や浮遊要塞に燃料切れ墜落をさせたくないときは
`upkeep = 0` と `no_fuel = NONE` を書いてください。**
逆に「地上でも補給が切れると消耗する」ゲームにするなら、
陸ユニットに `no_fuel = DAMAGE` を付けられます。

### 上限

- ユニット種別: **96** まで（現在30）
- **並び順に意味があります。** 途中に挿入するとセーブが壊れるので、
  作り替えるときは全部書き直すか、追加は末尾にしてください

## 5. 地形の書き方

```
[terrain LAVA]
name       = 溶岩              ← 画面に出る名前
char       = L                 ← .map ファイルで使う1文字（重複禁止）
def        = 0                 ← 防御補正（%）
cost_foot  = 4                 ← 移動コスト（2倍整数。2=通常1マス分）
cost_wheel = 0                 ← 0 = 進入不可
cost_track = 0
cost_air   = 2
cost_sea   = 0
cost_sub   = 0
income     = 0                 ← 毎ターンの収入
capturable = 0                 ← 1で占領対象
produces   = LAND              ← 生産できる系統（LAND/AIR/SEA。それ以外は生産不可）
supplies   = FOOT,WHEEL,TRACK  ← ここで補給される移動タイプ（カンマ区切り）
                               ←  LAND と書けば FOOT,WHEEL,TRACK の略記
hide       = 1                 ← 1で「隣接しないと中の敵が見えない」（森など）
hq         = 0                 ← 1で司令部（取られたら負け）
color      = 0xCC4422          ← 絵がないときの塗り色
```

**上限は 32 種類まで**（現在13なので**残り19枠**）。
さらに必要なら `src/core/types.h` の `MAX_TERRAIN` を増やせます（索引は1バイトなので255まで）。

### 現在の地形文字

| 文字 | 地形 | 文字 | 地形 |
|---|---|---|---|
| `.` | 平地 | `c` | 都市 |
| `=` | 道路 | `f` | 工場 |
| `w` | 森 | `a` | 空港 |
| `^` | 山 | `p` | 港 |
| `r` | 川 | `h` | 丘 |
| `~` | 海 | `H` | 首都 |
| `x` | 圏外（マップの形を作る。描画もされない） | | |

## 6. マップとキャンペーン

### `.map` の構造

```
[map]
name = 竜の谷
width  = 34
height = 25
turns  = 52              ← 制限ターン（0=無制限）
timeout_winner = -1      ← ターン切れ時の勝者（-1=引き分け）
funds0 = 1550            ← 初期資金
funds1 = 1550
income_scale = 100       ← 収入倍率（%）
objective_count = 10     ← 拠点n個確保で勝利（0=無効）
objective_player = 0

[terrain]
row = ww.w..........xxxxxxxxxxxxxxxxxxxx   ← 1行=1列ぶん。文字は terrain.def の char
row = ...

[owners]
own = 7,4,0              ← x, y, 陣営（0か1）

[units]
unit = 0,INFANTRY,9,7    ← 陣営, ユニットID, x, y
```

マップは手書きもできますが、`tools/gen_maps.py` で生成すると楽です。

### `.cpn`（キャンペーン）の主なキー

```
[node M01]
title = 第1作戦「竜の谷」
map   = maps/m01.map
art   = gfx/brief/m01.png       ← ブリーフィング1枚絵
reward = gfx/reward/m01.png     ← クリア報酬の絵
reward_video = gfx/anim/m01.mp4 ← クリア動画（絵より優先）
brief = 説明文（複数行書ける・最大8行）
enemy = EASY | NORMAL | HARD    ← 敵CPUの強さ
enemy_co = GRAF                 ← 敵指揮官のID
carry = 1                       ← 部隊を次の作戦へ持ち越す
bonus = 500                     ← クリア報酬の資金
par_turns = 20                  ← 作戦評価の基準ターン
no_reinforce = 0                ← 1で「敵増援なし」
next_win = M02
next_win_fast = M03             ← 早期クリア時の分岐先
fast_turns = 10
next_lose = LOSE

sub = MAX_LOSS:3:損失3部隊以内で勝て          ← 副目標（最大3個）
event = TURN:8 | SPAWN:1:DRAGON:20,7:2 | 竜が来た！   ← イベント（最大16個）
```

**副目標の種類:** `MAX_LOSS` / `MAX_TURNS` / `MIN_KILLS` / `KEEP_BLD` /
`CAPTURE` / `SURVIVE:数:ユニットID:説明`

**イベントの条件:** `TURN:n` / `BLD:陣営:n` / `LOSS:陣営:n` / `AREA:陣営:x,y:半径`
**イベントの動作:** `MSG` / `SPAWN:陣営:ユニットID:x,y[:体数]` / `FUNDS:陣営:額`

## 6-2. 書き間違いはどう分かるか

**`.def` と `.map` の未知のキーは読み込みエラーになります。**
ファイル名・行番号つきでメッセージが出て起動が止まるので、
打ち間違いは静かに無視されずに済みます。

一方、**次のものはエラーになりません**。気をつけてください。

| 状況 | どうなるか | 気づき方 |
|---|---|---|
| `text_ja.def` にキーが無い | **キー名がそのまま画面に出る**（`PANEL_ATK_FMT` と表示される） | 画面を見れば分かる |
| 絵・音のファイルが無い | 図形描画／無音になる。ゲームは続行 | 起動時のログに「読込失敗」とパスが出る |
| `produces` に知らない値 | 「生産不可」として扱われる | 拠点で生産メニューが出ない |
| 副目標の数値がマップと噛み合わない | 達成不能／開始時点で達成済み | `test_core.exe` が検出する |
| イベントの座標がマップ外 | 何も起きない | `test_core.exe` が検出する |

ログはコンソールに出ます。見えないときは次のようにすると残せます。

```
hexwars.exe 2> log.txt
```

## 7. C を触らないと変えられないもの

ここに挙げたものは、いまのところコードに埋まっています。
**どれも作り替えを止めるほどではありませんが、知っておいてください。**

| 内容 | 場所 | 備考 |
|---|---|---|
| **天候3種と効果** | `src/core/game.c` の天候セクション | 名前は `text_ja.def` で変更可。マップの `weather = 0` で無効化できる |
| **必殺技の5種類** | `src/core/game.c` の `game_co_activate` | HEAL/RUSH/STRIKE/FUNDS/SCOUT |
| **勝利条件の種類** | `game_check_victory` | 首都占領 / 全滅 / 拠点n個 / ターン切れ |
| **占領に必要なHP（20）** | `types.h` の `CAPTURE_HP` | |

### 上限を増やしたいとき

`src/core/types.h` の以下を書き換えて再ビルドします。
**セーブ形式に影響するので、作り始める前にやってください。**

```c
#define MAX_MAP_W        64
#define MAX_MAP_H        64
#define MAX_UNITS       200   /* 盤上のユニット総数 */
#define MAX_UNIT_TYPES   96   /* ユニットの種類数（現在30） */
#define MAX_TERRAIN      32   /* 地形の種類数（現在13） */
#define MAX_COMMANDERS   16
#define MAX_CAMPAIGN_MAPS 20
#define MAX_EVENTS       16   /* 1作戦のイベント数（32が上限） */
```

文言は `src/ui/text.c` の `MAX_TEXTS 512`（現在205）。上限を超えると起動ログで知らせます。

**索引は1バイトなので、ユニットも地形も255種類までは安全に増やせます。**
これらは配列の大きさだけの話で、**セーブ形式には影響しません**
（セーブに入るのは種別の番号で、読み込み時に `.def` の実数で検証しています）。

## 8. 作業の進め方（おすすめ）

1. **`text_ja.def` から始める** — 用語を全部その世界のものに書き換える。
   これだけで一気に雰囲気が変わり、何が足りないかが見えてきます
2. **`terrain.def`** — 地形が世界観を決めます。先に決めるとマップが作れます
3. **`units.def`** — 絵はあとで良いので、まず性能と名前だけ
4. **テストマップを1枚** — `data/maps/test_arena.map` を複製して試す
5. **バランスを見る** — `build/sim_ai.exe` でCPU同士を戦わせると、
   決着ターン数と損失が出ます。極端な数字が出たら性能を調整
6. **キャンペーンを組む** — 副目標とイベントは後から足せます
7. **絵と音を差し替える** — 最後で良いです

### 動作確認

```
build\test_core.exe    ← ルールの単体テスト（ALL TESTS PASSED が出ればOK）
build\sim_ai.exe       ← CPU同士の通し対戦（バランス確認）
```

`test_core.exe` は `data/maps/test_arena.map` に依存しています。
**このマップは変更しないでください**（テストが壊れます）。
