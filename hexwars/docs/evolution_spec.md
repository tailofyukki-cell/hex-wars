# ユニット進化 仕様

**2026-08-29 実装済み。** 以下は実装後の仕様（ドラフト時からの変更点も反映）。
スマホ向けの一覧は Artifact 版がある。

経験値が満タン（rank 5 / exp 100）になったユニットを、**その特性を伸ばした上位種**へ
任意で進化させる仕組み。実装前の設計メモ。

---

## 1. 基本ルール（確定事項）

| 項目 | 内容 |
|---|---|
| 条件 | `exp == 100`（rank 5）かつ進化先が定義されている |
| 任意 | プレイヤーが選ぶ。進化しないまま戦い続けてもよい |
| 経験値 | 進化すると **exp = 0 にリセット**（rank 5 → 0） |
| 生産 | 進化後のユニットは **生産不可**。進化でのみ入手できる |
| 不可逆 | 元には戻せない |

### 進化のコストは「経験値リセット」そのもの

現行の熟練度効果は **rank ごとに攻撃 +3% / 防御 +3%**（`battle.c` の
`atkmod = 100 + unit_rank*3` / `defmod = 100 + unit_rank*3`）。
rank 5 は **攻撃 +15% / 被ダメージ -13%** に相当する。

進化するとこれを全部失うので、**進化直後は一時的に弱くなる**。
つまり進化先の強化幅は「+15%/+15% を取り返してなお余りある」必要があり、
かつ「それでも今すぐ進化すべきか」を悩ませる程度に留めたい。

- 目安: **実効戦闘力で +25〜40%** ＋ 質的変化を1つ
- 進化直後に前線から一度下げる判断が生まれるのが理想

## 2. 実装に必要なもの（データ・コード）

### データ（units.def）

```
[unit TANK]
evolve_to = TANK_V      # 進化先のユニットID（無ければ進化できない）

[unit TANK_V]
no_produce = 1          # 生産メニューに出さない（進化でのみ入手）
```

`UnitType` に `char evolve_to[24];` と `uint8_t no_produce;` を追加。
**進化先は units.def の末尾に足すこと**（型 index が保存されるためセーブ互換の都合）。
型 index は1バイトなので、31 → 54 種に増えても `SAVE_VERSION` は据え置きでよい。

### コード

| 対象 | 変更 |
|---|---|
| `core/game.h/c` | `game_can_evolve(g, ui)` / `game_evolve_unit(g, ui)` を追加 |
| `core/game.c` | `game_type_buildable_at` で `no_produce` を除外 |
| `ui/screen_battle.c` | 行動メニューに「進化」。**不可逆なので確認を挟む** |
| `data/text_ja.def` | `ACT_EVOLVE` / 確認文言 / 進化演出のポップアップ |
| `core/ai.c` | CPUの進化判断（後述） |
| `tests/test_core.c` | 条件・リセット・生産不可・不可逆の検証 |

### 進化時の状態の扱い（要決定）

- **HP**: 維持（推奨）。満タンにすると前線で回復手段になり強すぎる
- **燃料・弾薬**: 新上限で満タン（推奨）。上位種は燃料上限が上がることが多く、
  比率維持だと進化した瞬間に息切れする
- **行動**: 進化したターンは `UF_DONE`（推奨）。移動＋進化＋攻撃を1手番でやらせない
- **搭載中**: 輸送に乗ったままの進化は不可（`UF_LOADED` は弾く）

## 3. 前提となる2つの制約（要判断）

### 制約A: 非戦闘ユニットは経験値が入らない

経験値は `game_attack` の中でしか増えない（与ダメ×2、撃破+20、反撃も同様）。
攻撃力がオール0の次の8種は**永久に rank 5 に到達できない**。

> トラック / 輸送ヘリ / 輸送艦 / 輸送機 / 補給車 / 補給機 / 補給艦 / 偵察機

**選択肢**

1. **これらは進化なし**（実装は最小。ただし支援系だけ仲間外れになる）
2. **非戦闘の功績にも経験値を与える**（推奨）。例:
   - 補給1回ごと `exp +6`（`game_supply_adjacent` の補給数ぶん）
   - 揚陸・降車1体ごと `exp +8`（`game_unload_unit`）
   - 占領完了 `exp +15`（`game_capture`）※歩兵系の育成も早くなる
   - 敵ユニットを新規に発見 `exp +3`（偵察機の存在意義）

   → ルール変更なので要承認。歩兵の育成速度が上がる副作用がある。

### 制約B: 輸送枠は最大2

`Unit.cargo[2]` の固定配列。**「輸送枠 +1」を進化特典にはできない**
（構造体とセーブ形式の変更が必要）。輸送・空母系の進化は
「積載量以外」（速度・防御・視界・燃費・艦載機の回復量）で差を付ける。

## 5. CPUの進化判断（案）

- 原則、**進化できるなら進化する**（rank 5 は上限で、それ以上ためても無駄なため）
- ただし **HP が高いときだけ**（例 `hp >= 7`）。瀕死のまま進化すると
  熟練度を失って即撃破されるので、いったん引く判断と両立させる
- 難易度で差を付ける: EASY は 5割の確率で見送る／HARD は常に最適で進化

## 6. バランス上の注意

- **戦艦の射程 2-6 は盤面を支配しかねない**。sim_ai で c11/c12/m03 を複数シード計測し、
  海戦マップの決着率が偏らないか確認すること
- 高射砲 → 重高射砲の **対装甲 5→70** は影響が大きい。移動1のまま据え置くことで
  「置き場所を選ぶ対戦車砲」に留める
- 進化を入れると**長期戦ほど強くなる**ので、ターン切れ引き分けの多いマップ
  （c03/c04/c07/c10）の性格が変わる可能性がある
- 経験値を非戦闘行動でも与える場合（制約A案2）、**歩兵の占領による育成が速くなる**。
  占領 exp は控えめ（10〜15）から試すこと

## 7. 段階的な進め方（提案）

1. **E0 基盤**: `evolve_to` / `no_produce` をデータとパーサに追加。
   `game_can_evolve` / `game_evolve_unit` と単体テスト。UIはまだ無し
2. **E1 UI**: 行動メニューに「進化」＋不可逆の確認。演出（バナー/SE）
3. **E2 戦闘系の進化先**: 歩兵・装甲・航空・海上の23種を units.def 末尾に追加
4. **E3 AI**: CPUの進化判断
5. **E4 支援系**（制約Aの解決とセットで判断）
6. 各段階で `test_core` / `sim_ai` を通す

## 8. 実装メモ（2026-08-29）

ドラフトから変わった点と、実装して分かったこと。

- **射程減衰**を先に単独で入れた。`battle.c` の `base_damage_x10` で天候倍率と同じ形で掛ける。
  `RANGE_FALLOFF_PCT 5` / `RANGE_FALLOFF_MIN 50`。距離0（同一セルの別レイヤー）は
  差が負になるので0で下限を切っている。
- **超弩級戦艦は射程 2-7**（ドラフトの 2-6 から変更）。減衰込みで最遠射
  `95×0.75=71` は元の戦艦の最遠射 `85×0.85=72` とほぼ同じ＝威力据え置きで射程だけ伸びる。
- **搭載枠を 2→4** に拡張（`MAX_CARGO`）。大型空母が4機積むため。
  セーブは `SAVE_VERSION 8`、読み込みは `ver >= 8 ? 4 : 2` で **v7以前のセーブもそのまま開ける**。
- **大型空母は修理 +2→+3**、積載4、cost 1400。
- **経験値の配点**（`game.c` の `EXP_*`）: 降車+10 / 物資1消費+1 / 索敵の1歩+1 /
  艦載機1機の整備+2 / 占領完了+15。**1ランク=20、満タン=100** なので、
  ドラフト時にユーザーが想定していた「1ランク=100」前提の数値を1/5に換算してある。
- **偵察の経験値は往復で稼げる**（`visible[]` は今見えているかだけを持ち、探索済みの記録は
  作っていない）。「偵察の仕事は見えない場所を見ることだから許容する。遊んでみて
  おかしければ変える」というユーザー判断。索敵OFFのときは加算しない。
- **進化できる場所**は `terrain.def` の `supplies` をそのまま使う＝陸は街/工場/首都、
  空は飛行場、海は港。自軍所有であることも条件。新しいデータ項目は足していない。
- **AIの進化は日和見的**。`hp >= 7` かつ補給拠点の上に居るときだけ進化する。
  拠点まで下がりに行く判断は入れていないので、CPU戦では進化が起きにくい。
- sim_ai 実測（25戦）: 決着 7→7、総ターン 2143→2117、総損失 10841→11621(+7%)。
  進化と減衰を入れてもバランスは大きく動いていない。
